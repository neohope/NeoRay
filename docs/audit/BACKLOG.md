## 一、等到出现明确痛点再做的（4 项）

### B1. `exec_session` 的 `Wait` 与 `StdoutPipe` 并发读

- **问题**：`os/exec` 要求先读完 `StdoutPipe`/`StderrPipe` 再 `Wait()`；当前两者并发，
  进程快速退出时 `Wait` 会关掉读端，尾部输出可能丢（只记 Debug 日志）。
- **触发条件**：出现"命令明明成功了，但最后几行结果没拿到"的反馈。
- **为什么暂缓**：需要重排读协程与 `Wait` 的时序，改动面比它现在造成的损失大；
  第五轮已把"退出后立即回收导致丢输出"（S3）修掉，日常使用基本不触发。
- **预估**：半天（含回归测试）
- **位置**：`neoray/internal/tools/exec_session.go:152` 附近

### B2. `apply_patch` 复用文件策略 + patch/write 互斥

- **问题**：`apply_patch` 不检查 `blocked_extensions` / `max_file_size`；
  同一文件的 patch 与 `write_file` 并发时后写覆盖前者。
- **触发条件**：出现"文件被莫名改坏"、或需要在工作区里禁止某些扩展名。
- **为什么暂缓**：需要引入按路径的写锁，影响所有写工具的调用链；
  当前单用户、串行对话下并发写同一文件概率很低。
- **预估**：1 天（含按路径锁 + 策略复用 + 测试）
- **位置**：`neoray/internal/tools/patch.go:315`、`filesystem.go:216`（两条写路径都不查策略）

### B3. `FileStore.Save` 锁内序列化 + 落盘

- **问题**：`Save` 持 store 写锁期间做 `json.MarshalIndent` + `WriteFile` + `Rename`，
  会话大时所有会话接口排队。
- **触发条件**：会话数或单会话历史变大后，列表/详情接口出现可感知延迟。
- **为什么暂缓**：需要改成"锁内取快照、锁外写盘"，并加每会话写锁保证顺序；
  当前规模下瓶颈不在这里。
- **预估**：半天
- **位置**：`neoray/internal/session/filestore.go:131`（`Save` 内 `s.mu.Lock()` 覆盖序列化与写盘）

### B4. `**` 通配与 `allowed_extensions` 的通配语义

- **问题**：`filepath.Match` 不支持 `**`；`allowed_extensions = [".*"]` 被当成字面量。
  随附模板里这两种写法都有，示例与实际行为不一致。
- **触发条件**：需要按目录层级写 glob，或需要在模板里用 `.*` 表示"全部允许"。
- **为什么暂缓**：这是**产品决定**而非纯 bug——要先定"配置里什么算通配"，
  贸然支持会导致现有配置语义漂移。
- **预估**：半天（含模板与文档同步）
- **位置**：`neoray/internal/tools/search.go:744`、`filesystem.go:233`

- **建议节奏**：不追求数字，按"改动驱动"补——每次修 bug 顺手补一条能复现的测试。

- **注意**：`govulncheck` 已在 CI 中改为阻塞任务，安全问题会自己冒出来。

## 三、按决策保留（1 项）

### B8. F15：API 请求方自称身份

- **问题**：`channel_id` / `user_id` 来自 query 或 header，持 API Key 者可读任意会话。
- **为什么不修**：单用户、单密钥部署，改成"身份来自认证上下文"需要同时改 Web UI 调用约定，
  收益低于成本。
- **什么时候做**：多用户改造时，与鉴权体系一并处理。
- **位置**：`neoray/internal/api/handlers.go`（会话读取路径）

## 四、明确不打算做

| 想法 | 理由 |
|---|---|
| shell 路径检查做成完整命令解析（AST / 语法级沙箱） | 静态检查永远有漏；真正的隔离应交给 bwrap（已支持）。策略层只需保证"没有整类命令被无条件放过" |
| 给所有 goroutine 加 recover | 长生命周期循环值得加（已加频道分发、流式解析）；一次性短协程套 recover 会掩盖真 bug |
| 现在实现 sqlite 会话存储 | 文件存储在单用户规模够用；先接上 `max_sessions` 更划算 |
| 把 consolidator 的索引重构成对象 | 坐标已统一，重构留到需要增量压缩时 |
| TUI 撤掉 | 它是 `--tui` 的可选模式，不影响服务端 |
